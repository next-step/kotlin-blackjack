# 블랙잭 1단계

## 기능 요구사항
1. 게임 참가자를 입력받는다.
- 쉼표 기준으로 이름 분리
- 유효성
  - 빈 이름 금지
- 입력 : 게임에 참여할 사람의 이름을 입력하세요.
2. 카드 나누기
- 딜러와 참가자에게 카드를 2장씩 나눈다.
- 카드는 중복될 수 없다.
- 출력
  - 딜러 + 참가자 카드 분배 
    - 딜러와 pobi, jason에게 2장의 나누었습니다.
  - 딜러 카드 공개 (2장 중 1장)
    - 딜러: 3다이아몬드 
  - 참가자 카드 공개 (2장 중 2장 모두)
    - pobi카드: 2하트, 8스페이드 
3. 참가자 카드 뽑기
- 21점이 넘지 않을 때까지 카드를 뽑는다.
- 21점이 넘어가면 카드 뽑기를 생략한다.
- 카드는 중복될 수 없다.
- 카드의 숫자 계산은 카드 숫자를 기본으로 하며, 예외로 Ace는 1 또는 11로 계산할 수 있으며, King, Queen, Jack은 각각 10으로 계산한다.
- 입력 : pobi는 한장의 카드를 더 받겠습니까?(예는 y, 아니오는 n)
- 출력 : pobi카드: 2하트, 8스페이드, A클로버
- 유효성
  - y,n 이외의 값을 입력할 수 없다.
4. 딜러 카드 뽑기
- 딜러는 처음에 받은 2장의 합계가 16이하이면 반드시 1장의 카드를 추가로 받아야 하고, 17점 이상이면 추가로 받을 수 없다.
- 카드는 중복될 수 없다.
- ace가 나왔을 때, 랜덤으로 1 또는 11 중에 선택한다.
- 출력 
  - 16점 이하 : 딜러가 16점이하라 한장의 카드를 더 받았습니다.
  - 17점 이상 : 딜러가 17점 이상이라 카드를 뽑지 않습니다.
5. 결과 공개
- 딜러와 참가자의 카드를 공개한다.
- 출력
  - 딜러 카드: 3다이아몬드, 9클로버, 8다이아몬드 - 결과: 20
  - pobi카드: 2하트, 8스페이드, A클로버 - 결과: 21
  - jason카드: 7클로버, K스페이드 - 결과: 17
6. 승패 공개
- 딜러와 참가자의 승패를 공개한다.
- 출력
  - 딜러: 1승 1패
    pobi: 승
    jason: 패

## 프로그래밍 요구사항
- indent(인덴트, 들여쓰기) depth를 2를 넘지 않도록 구현한다. 1까지만 허용한다.
  - 예를 들어 while문 안에 if문이 있으면 들여쓰기는 2이다.
  - 힌트: indent(인덴트, 들여쓰기) depth를 줄이는 좋은 방법은 함수(또는 메서드)를 분리하면 된다.
- 모든 기능을 TDD로 구현해 단위 테스트가 존재해야 한다. 단, UI(System.out, System.in) 로직은 제외
  - 핵심 로직을 구현하는 코드와 UI를 담당하는 로직을 구분한다.
  - UI 로직을 InputView, ResultView와 같은 클래스를 추가해 분리한다.
- 함수(또는 메서드)의 길이가 10라인을 넘어가지 않도록 구현한다.
  - 함수(또는 메소드)가 한 가지 일만 하도록 최대한 작게 만들어라.
- 배열 대신 컬렉션을 사용한다.
- 모든 원시 값과 문자열을 포장한다
- 줄여 쓰지 않는다(축약 금지).
- 일급 컬렉션을 쓴다.
- 모든 엔티티를 작게 유지한다.
- 3개 이상의 인스턴스 변수를 가진 클래스를 쓰지 않는다.
- 딜러와 플레이어에서 발생하는 중복 코드를 제거해야 한다.
